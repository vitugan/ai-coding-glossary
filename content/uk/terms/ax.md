Зручність для агента (Agent experience) — наскільки добре [середовище](./environment.md) налаштоване, щоб [агент](./agent.md) міг якісно працювати з кодовою базою. Це аналог [зручності для розробника](./dx.md), але з погляду агента. Коли той самий агент добре працює в одному репозиторії і погано в іншому — з тією самою [моделлю](./model.md) й тією самою [оболонкою](./harness.md), — різниця зазвичай саме в AX. Першим інстинктом буває звинуватити модель або переписати промпт, але виправляти найчастіше треба в репозиторії.

Хороша зручність для агента має три основні складові:

| Складова         | Що означає гарна зручність для агента                                                                                                                                                                                                                                                            |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Automated checks | Швидкі, детерміновані [автоматичні перевірки](./automated-check.md) — типи, тести, лінти, — які дозволяють агенту самостійно виправляти помилки без участі людини                                                                                                                                |
| Architecture     | Кодова база, якою агент може користуватися, не читаючи все підряд: передбачувана структура, багато поведінки за невеликими інтерфейсами, назви, що говорять про суть речей                                                                                                                       |
| Free context     | [AGENTS.md](./agents-md.md), [skills](./skill.md) та [tools](./tool.md) залишаються лаконічними, тому більша частина [контекстного вікна](./context-window.md) доступна для конкретного завдання, і агент залишається в [розумній зоні](./smart-zone.md) замість того, щоб потонути в інформації |

Зручність для агента AX та зручність для розробника DX перетинаються — хороші перевірки та чиста архітектура допомагають обом аудиторіям, — але мають і відмінності. Люди толерують «корпоративні знання», повільний CI та «запитай у Сари про білінговий модуль»; агенти — ні. Агенти не отримують переваг від підказок у IDE чи гарних панелей моніторингу; їм потрібні помилки у вигляді тексту в [результаті інструменту](./tool-result.md). Кодова база може мати хорошу DX і погану AX.

## avoid

трактувати AX як синонім DX — аудиторії потребують різних інвестицій.

## usage

"Агент пише чудовий код в репозиторі API і сміття в фронтенді."

"В репозиторі API строгі типи і швидка тестова збірка, а в фронтенді ні того, ні іншого, плюс сорок завжди завантажених скілів. Це розрив AX, а не проблема моделі."
