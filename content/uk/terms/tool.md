Функція яку [оснащення](./harness.md) надає [агенту](./agent.md) для виклику — Read, Write, Bash, Search. Через інструменти агент бачить середовище і діє в ньому: він не може бачити середовище, окрім як через [результати інструментів](./tool-result.md) і не може змінити його, окрім як через [виклики інструментів](./tool-call.md). Кожен виклик інструменту коштує додаткового [запиту до провайдера моделі](./model-provider-request.md), оскільки результат повинен повернутися до моделі, перш ніж вона зможе вирішити, що робити далі.

Інструменти, які постачаються з більшістю агентів:

| Tool   | What it does                                                             |
| ------ | ------------------------------------------------------------------------ |
| Read   | Повертає вміст файлу як результат інструменту                            |
| Write  | Створює або редагує файл у [файловій системі](./filesystem.md)           |
| Bash   | Запускає команду оболонки та повертає її вивід                           |
| Search | Знаходить файли або текст, що відповідають шаблону, по всій кодовій базі |

Інструмент визначається трьома речами: назвою, описом того, що він робить, і схемою для його параметрів. Оболонка надсилає ці визначення [моделі](./model.md) з кожним запитом, і модель вибирає інструмент так само, як вона генерує все інше — шляхом запису [токенів](./token.md), в даному випадку структурованого виклику з аргументами. Сама модель нічого не виконує; оболонка читає виклик, запускає функцію та надсилає результат назад.

Список інструментів визначає, що може робити агент. Компетентна модель з обмеженим набором інструментів — це вузький агент: вона буде направляти все через те, що має, тому агенти так сильно покладаються на Bash — shell це один інструмент, який охоплює більшу частину системи. Щоб чисто надати агенту можливість, додайте інструмент для нього; [MCP](./mcp.md) це стандарт для підключення інструментів з-за меж оболонки.

Визначення інструментів займають [контекст](./context.md) при кожному запиті, тому великий набір інструментів має постійну вартість ще до виклику будь-якого інструменту — і багато інструментів з схожими описами погіршують здатність моделі вибирати правильний.

## usage

"Чи може агент робити запити до staging безпосередньо?"

"Додайте інструмент `psql` до оболонки, з обмеженим доступом на читання до staging. Без інструменту агент не бачить нічого за межами файлової системи."
